## Traps (all cost time this session)

- **Never `taskkill /IM chrome.exe`** (closes the user's own Chrome/Zephyrus). Filter by profile path in PowerShell: `Get-CimInstance Win32_Process -Filter "Name='chrome.exe'" | Where-Object { $_.CommandLine -like '*zeph_perf\<profile>*' } | Stop-Process`. A leftover test browser also holds `resources.pak`/`chrome.dll` and breaks the next build ("Permission denied: resources.pak").
- Do not build two Chromiums at once; the shell is very slow while a build runs. Never `grep -r` the tree (hangs); use `git grep`/Grep tool.
- Editing `generated_resources.grd` or a widely included header recompiles nearly everything.
- Bash heredoc Python mangles `\r`, `\f`, `\n` in Windows paths and strings: use forward slashes or write files with the Write tool.
- `--enable-logging=stderr` ignores `--log-file`; use `--enable-logging --log-file=...`.
- Settings opens as a popup (not a debuggable tab), so CDP scripts cannot easily reach the settings page.
- `mini_installer` does not notice a copied payload file; delete `chrome.7z`/`chrome.packed.7z`/`mini_installer.exe` to force it. `package_installer.py` refuses to overwrite (move the old exe).
- The installer cannot be verified from the agent shell (MSIX redirection): the user must run it.
- `cap.py`/`glance_drive.py` honour env `ZEPH_EXE`; `seed_profile(extra_prefs={"zephyrus.ui_layout": 0|1|2})` uses dotted keys (0 floating sidebar, 1 horizontal tabs, 2 classic sidebar, default 2). In layout 0 the pin button (second icon from the left of the minimise button) enters compact mode.
